# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Este repo es **Anarchivo Atelier** (nombre provisional; GitHub `telefante/anarchivo-atelier`, MIT): se comparte para que otras personas lo usen con su propio archivo. En el Atelier vive como `dashboard/` dentro del playbook Atelier Negrón. El `CLAUDE.md` de la raíz del repo (idioma, tono, estructura de carpetas, qué hacer / qué no) también aplica; aquí solo va lo específico del dashboard. Detalle largo en `README.md`.

**Genérico por defecto.** Nada personal va en el código ni en los valores por defecto (`scripts/config.mjs` `DEFAULTS`): nombre, firma, presentación de Conversar, destino de Publicar y carpetas «nunca leer» de cada quien van en `anarchivo.config.json`, que **no se versiona** (plantilla: `anarchivo.config.example.json`). Sin configuración, el dashboard abre `ejemplo/` (archivo de muestra, contenido neutro inventado). El del Atelier tiene `"playbook": ".."`. **Solo local por defecto:** lo online (Publicar ↑ / `deploy.sh`, y `ingest/` en Railway) queda apagado e invisible sin configurar — «Publicar ↑» aparece solo con `publicar.destino` (o `REMOTE_BASE`), la subida remota solo con `PUBLIC_INGEST_URL` en el build. En el Atelier ambos están configurados.

## Comandos

```
npm run dev       # node scripts/sync.mjs && astro dev
npm run build     # sync + astro build → dist/
npm run preview   # sirve dist/
npm run sync      # solo regenerar src/data/index.json
npm run add-image -- ./foto.jpg "Descripción" "tag1,tag2"
```

No hay tests ni linter. Verificar cambios corriendo `npm run dev` y mirando `/anarchivo` en el navegador.

## Arquitectura

- **Solo lectura, local.** `scripts/sync.mjs` lee los `.md` del playbook (padre de `dashboard/`, o `PLAYBOOK_DIR`) y escribe `src/data/index.json` (`.gitignore`d, se regenera en cada `dev`/`build`). Las páginas `.astro` solo consumen ese JSON. Si no encuentra el playbook cae a datos de ejemplo. `BLOCKED` en `sync.mjs` lista lo que nunca lee (`_archivo-trabajo/`, `bewerbungen/`, `dashboard/`…). El sync también calcula similitud visual CLIP entre ~900 imágenes (≈1 min); el modelo se descarga la primera vez.
- **Artefactos** (`02-artefactos/<slug>/<slug>.md` + `imagenes/`): `readArtefactos()` los lee como nodos `kind: 'artefacto'` (id `art:<slug>`), enlazados a su obra por `proyecto:` (slug del dossier) y `relacionados:` (proyectos en curso); sus fotos entran a la Mesa como cualquier imagen. En Anarchivo: columna propia en Carpetas, filtro por tipo, visibles desde el nivel Obra.
- **Constelaciones** (`09-constelaciones/<slug>.md`): `readConstelaciones()` las lee como nodos `kind: 'constelacion'` (id `cst:<slug>`), enlazadas a sus imágenes y textos (`constela`) y, si declaran `concepts:`, al vocabulario — sin contar como obra del concepto (no cambian tamaño ni orden de las áreas). En la Mesa (`mesa/constelaciones.js`): ⌘/Ctrl+clic → «+ Constelación» crea una o suma a una existente; «Constelaciones» las lista y cada una vuelve como capa (id de capa = id del nodo); si la capa cambia, su chip ofrece «guardar ↥». En la versión publicada no hay disco: quedan en `mx.constelaciones` (este navegador) y en local se pueden pasar al playbook.
- **Home = `/anarchivo`** (`/` redirige). Es una página aparte, sin la barra lateral de `Base.astro`. `/resumen`, `/ciclo-de-vida` y `/grafo` son versiones congeladas: no desarrollarlas salvo petición explícita. `/bitacora` es solo lectura.
- **Anarchivo** (`src/pages/anarchivo.astro` + `src/styles/anarchivo.css` + `src/scripts/anarchivo/`): la página solo trae HTML y arranque (el JSON del grafo va inline en `#ax-data`). Casi toda la UI se genera con `innerHTML`, por eso el CSS es global a propósito (un estilo con scope no la alcanzaría). `main.js` cablea; el resto son módulos por responsabilidad (`graph.js` d3, `cards.js`, `windows.js`, `vistas.js`, `top.js`, `mesa/*`).
- **Conversar** (`src/scripts/anarchivo/chat.js` + `scripts/chat.mjs`, solo en `npm run dev`): chat con un modelo local de LM Studio (`LMSTUDIO_URL`, por defecto `http://localhost:1234`). El servidor arma el contexto en cada turno — lo nombrado (@, «+ lo que tengo delante») entero, y lo más parecido a la pregunta buscado en el texto completo de los `.md` que el índice conoce y en las notas de imágenes —; con un modelo de visión (vlm) las fotos nombradas viajan reducidas a 768 px. Lee las respuestas en voz alta con las voces del sistema (Web Speech API; primero es-MX/latam, por defecto Paulina). La conversación vive en `localStorage` «ax-chat-v1» (aparte de `mx`), se descarga como `.md` y se guarda sola en `10-conversaciones/` (ver excepciones abajo).
- **Ajustes** (`scripts/config.mjs` + `scripts/ajustes.mjs` + `src/scripts/anarchivo/ajustes.js`): nombre del archivo, firma, ruta del playbook, nombres de carpetas, `nuncaLeer`, vocabulario, Conversar (LM Studio, guardar, *presentación*) y Publicar, en `dashboard/anarchivo.config.json`. **Ningún script escribe nombres de carpeta a mano:** se toman de `cargar().carpetas` (los valores por defecto son los del Atelier). Las variables de entorno de siempre mandan sobre el archivo. finder/archivo leen las rutas al arrancar (cambiarlas pide reiniciar `npm run dev`); chat y deploy, en cada uso. El servicio `ingest/` de Railway no lee los ajustes: sigue con los nombres del Atelier.
- **Convención de módulos:** no importan la página; lo que necesitan de ella (y las llamadas «hacia arriba») llega por un `ctx` explícito a `initX(ctx)`. d3 viene de npm, sin red.

## Cosas que no se tocan sin pedirlo

- Las capas de datos del grafo (menciones en bitácora/ensayos/convocatorias, límite de obras publicadas por concepto). El layout por áreas/conjuntos (`graph.js`: fuerzas `concepto` ponderadas por especificidad, cascos en `gBlobs`, niveles Figura/Obra/Todo) ya es el vigente; las relaciones `visual` (CLIP) no entran en la física.
- `mx` (estado de la Mesa, `localStorage` «ax-mesa-v1»): un solo objeto, clave y esquema fijos — es el único dato del usuario que no se regenera con `sync`.
- Slugs de `concepts:` en el grafo: vienen del vocabulario del dossier (`dossierNegronvanGrieken/src/data/concepts.ts`); no inventar.
- No añadir dependencias de servidor ni escribir de vuelta al playbook. Excepciones pedidas: `add-image.mjs`, y `scripts/finder.mjs` (solo en `npm run dev`): «Mostrar en Finder» y la **nota de una imagen** de la Mesa, que al pulsar «Guardar» se escribe en su `imagenes.yaml` (campo `nota`) y en los metadatos del propio archivo (XMP `dc:description`, con `exiftool`). Las imágenes del dossier son de otro repositorio y se publican: su nota va solo a `02-artefactos/imagenes-dossier.yaml`, nunca al archivo. Y **«Subir fotos»**: guarda imágenes nuevas en `08-imagenes/` (sin pisar las existentes) y relanza `sync`; esa carpeta entra al grafo como el proyecto «Sueltas». Y las **constelaciones**: `/__constelacion` crea `09-constelaciones/<slug>.md` (nunca pisa uno existente) o cambia solo las listas `imagenes`/`textos` de uno que existe — título, texto y referencias que el índice no conoce se conservan — y relanza `sync`. Y **«Subir imagen» y «+ Artefacto»** (artefactos nuevos: carpeta y ficha en `02-artefactos/<slug>/`, fotos reducidas a 2000 px en png; el código compartido está en `ingest/core.mjs`): en local escriben al disco por `scripts/finder.mjs`; en la versión publicada, con `PUBLIC_INGEST_URL`, van al servicio de Railway `ingest/` (ver su README), que escribe en Nextcloud por WebDAV. Y **«Catalogar original»** y `npm run catalogar` (`scripts/archivo.mjs`): para un original grande (20–200 MB) que vive en una fuente declarada en `08-imagenes/archivo-fuentes.yaml`, escriben en el playbook solo su vista previa (jpg de 1600 px) y una entrada con campos `original_*` en el `imagenes.yaml` de su proyecto o de `08-imagenes/`; el original nunca se copia, se mueve ni se modifica, y un original ya catalogado (mismo sha256) se salta. Guía: `docs/documentar.md`. Y las **conversaciones** de «Conversar»: `/__conversacion` (en `scripts/chat.mjs`) crea `10-conversaciones/AAAA-MM-DD-<slug>.md` (nunca pisa otro) y luego reescribe solo ese archivo, y solo si su sha256 coincide con lo último que escribió; si se editó a mano, abre uno nuevo. «Guardadas» las lista (`/__conversaciones`), las abre en Obsidian o las muestra en Finder (`/__conversacion-abrir?con=obsidian|finder`, `open` de macOS, solo archivos de esa carpeta por nombre) y retoma una (`GET /__conversacion?archivo=`, que la lee de vuelta a mensajes por sus cabeceras `### <firma> · hh:mm` / `### modelo · <nombre> · hh:mm`; solo es reescribible si regenerarla da el archivo idéntico). El sync no lee esa carpeta. Y **«Ajustes»** escribe `dashboard/anarchivo.config.json` (del dashboard, no del playbook). El mismo servicio lanza `scripts/deploy.sh` desde el botón **«Publicar ↑»** (arriba a la derecha, solo en local, pide un segundo toque).

## Escritorio (`desktop/`)

App de macOS **Anarchivo** (Electron): una ventana sobre el mismo servidor de `npm run dev` — usa el de `localhost:4321` si ya corre; si no, corre `sync.mjs` y `astro dev` en un puerto libre (≥4322) con el `node`/`PATH` del shell de login, y lo apaga al salir. Tiene su propio `package.json`: Electron y `@electron/packager` viven solo ahí, no en las dependencias del dashboard. `npm start` (desarrollo), `npm run app -- --instalar` (arma `out/Anarchivo.app` y la copia a `~/Applications`), `npm run icono` (desde `build/icono.svg`). Menú: «Ajustes…» (⌘,) abre el panel; «Reiniciar el servidor» relanza la app (y su servidor) para que valgan rutas nuevas. La `.app` no lleva el dashboard dentro, solo anota su ruta. Detalle en `desktop/README.md`.

## Deploy

`scripts/deploy.sh` construye con `ATELIER_BASE` = la subcarpeta de «Ajustes → Publicar» (por defecto `/anarchivo/`; en el Atelier `/atelier/`) y hace rsync al destino de esos mismos ajustes (sin destino, no hace nada), protegido con Basic Auth (`scripts/setup-auth.sh`, una sola vez, mismo destino). El contenido es privado: el script nunca toca `.htaccess`/`.htpasswd`.
